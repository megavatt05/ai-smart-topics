# 03. Как работать с Qwen Coder: секреты продуктивности

## Что важно понимать
Qwen Coder и подобные модели очень сильны, когда вы работаете не “в одну строку”, а в формате:
- контекст;
- задача;
- ограничения;
- ожидания;
- критерии проверки.

Самая частая ошибка — давать модели слишком общий запрос вроде:
> “сделай мне приложение”

Вместо этого лучше:
> “создай минимальный сервис на Python, который принимает JSON, валидирует поля, пишет в SQLite и имеет unit tests; структура проекта: app/, tests/, README.md; выход — рабочий код без лишних зависимостей”.

## Секрет №1: давать структуру
Указывайте:
- назначение проекта;
- архитектуру;
- директории;
- интерфейс;
- правила стиля;
- формат вывода;
- ограничения по зависимостям.

## Секрет №2: разбивать задачи на этапы
Нельзя давать модель сразу огромный проект без roadmap.
Лучший способ:
1. Понять требования
2. Спросить план
3. Подтвердить архитектуру
4. Сгенерировать модуль
5. Проверить код
6. Уточнить ошибки
7. Добавить тесты

## Секрет №3: требовать план до кода
Полезная команда:
> “Сначала составь краткий план по файлам и логике проекта, затем напиши код по шагам, и после каждого шага проверяй результат.”

## Секрет №4: использовать “жёсткие ограничения”
Примеры:
- без внешних библиотек;
- Python 3.11;
- всё в одном файле;
- использовать Dataclasses;
- добавить unit tests;
- сохранить формат JSON и логирование.

## Секрет №5: просить critique
Можно попросить:
- найти возможные ошибки;
- перечислить потенциальные риски;
- предложить улучшения архитектуры;
- найти нежелательные зависимости;
- проверить логику на edge cases.

## Секрет №6: проверять результат
Модель может быстро генерировать код, но ответственность за качество остаётся у вас.
Проверяйте:
- синтаксис;
- тесты;
- отсутствие скрытых ошибок;
- соответствие тре��ованиям;
- корректность логики.

## Практический шаблон запроса
```text
Ты — senior engineer. Нужно создать проект X.

Требования:
- Python 3.11
- 3 слоя: API, service, repository
- SQLite
- unit tests
- clear README
- без лишних зависимостей

Сначала дай план по файлам и архитектуре.
Потом создай минимальный рабочий код.
После этого добавь тесты.
В конце перечисли риски и возможные улучшения.
```

## Ключевая мысль
Qwen Coder даёт сильный результат, когда вы задаёте не “общую задачу”, а “контролируемую инженерную задачу”.
